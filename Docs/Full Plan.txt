## 💡 Inspiration
Most voice assistants still operate in a **stateless, single-turn loop**: you ask for the weather, or you set a single timer, and the context evaporates the moment the response ends. Yet real household requests are naturally **multi-intent, stateful, and multimodal**. 

When someone says, *"Alexa, we're hosting Taco Night for 6 on Friday—remember Ben is gluten-free, warm up the patio lights at 7 PM, and put on a Latin jazz playlist,"* a single-turn wrapper fails. We built **LexaFlow** to demonstrate what **Alexa+** can truly become when powered by the **Model Context Protocol (`2025-11-25` Streamable HTTP)**, **Agent Skills**, and **Amazon Bedrock**: an autonomous household chief-of-staff that remembers context across sessions, orchestrates across multiple services in parallel, and renders rich **Multimodal Carousels & 1-Click Voice Purchasing Cards**.

## 🚀 What It Does
**LexaFlow** combines a spec-compliant **Streamable HTTP MCP Server (`2025-11-25`)**, a modular **Alexa+ Agent Skill (`SKILL.md`)**, and an interactive **Echo Show / Alexa+ Multimodal Simulator**:

1. **Autonomous Multi-Service Orchestration:** A single natural-language prompt decomposes into coordinated tool calls across four domains:
   - **Persistent Household Memory (`memory_get_or_update`):** Reads and updates a cross-session household graph (dietary restrictions, brand preferences, budget caps, and active plans).

## 🛠️ How We Built It
- **MCP `2025-11-25` Streamable HTTP Transport:** Built in Node.js & Express on a unified `/mcp` endpoint supporting JSON-RPC 2.0 `POST` requests and Server-Sent Events (`GET` stream) for server-to-client notifications.
- **AWS Bedrock Runtime (`@aws-sdk/client-bedrock-runtime`):** Integrated the Amazon Bedrock `ConverseCommand` API to pass our MCP tool schemas dynamically into foundation models (`Claude 3.5 Sonnet` / `Amazon Nova Pro`), complete with a deterministic local orchestration fallback so judges can test the repository immediately with zero cloud setup friction.
- **Context Relevance & Budget Optimization Model:** To decide which historical household facts to inject into the active Alexa+ prompt window without exceeding latency budgets, we score each stored memory fact $m_i$ using a time-decayed utility function:

$$U(m_i, q) = \alpha \cdot \text{sim}(m_i, q) + \beta \cdot e^{-\lambda \Delta t_i} + \gamma \cdot \mathbb{I}_{\text{safety}}(m_i)$$

where $\text{sim}(m_i, q)$ measures semantic overlap with the current utterance $q$, $\Delta t_i$ is the elapsed time since fact $m_i$ was confirmed, and $\mathbb{I}_{\text{safety}}(m_i)$ prioritizes critical household constraints such as severe food allergies or spending caps.
